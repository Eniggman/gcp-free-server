### 1.2. Почему архитектор рекомендует именно Opera MCP?

1. **«Рентген» страницы (Accessibility DOM) вместо слепых скриншотов:**
   Вместо разглядывания пикселей агент за доли секунды запрашивает у движка Blink структурное дерево доступности. Он видит не разноцветную картинку, а точную смысловую карту:
   `Button: "Create instance" [enabled=true, focused=false]`, `Checkbox: "Ops Agent" [checked=true]`. Ошибиться или нажать «не туда» при таком подходе технически невозможно.
2. **Нулевой конфликт за рабочий стол:**
   Агент выполняет команды программно через локальный WebSocket. Ты можешь одновременно переписываться в Telegram, листать код или пить кофе — физический курсор мыши остается полностью в твоем распоряжении.
3. **Работа в твоей живой сессии (без повторных логинов):**
   В отличие от "безголовых" браузеров (Puppeteer / Playwright), которые стартуют с пустого профиля и требуют заново вводить пароли и проходить двухфакторную аутентификацию (2FA) Google, MCP подключается прямо к открытой рабочей Opera со всеми твоими сохраненными куками и правами доступа.

У меня 2 ядра или нет?»*🧠 **Ответ архитектора:** В семействе машин E2 операционная система Ubuntu честно видит два ядра (`vCPU 1` и `vCPU 2`), что позволяет запускать параллельные потоки. При этом кремниевые ядра делятся гипервизором между пользователями:
>
> - В тарифе `e2-micro`: базово гарантировано **0.25 vCPU (25%)**.
> - В тарифе `e2-small` (v2.0): базово гарантировано **0.50 vCPU (50%) + мощный CPU burst**.

### 3.3. Вопрос 3: Производительность AI-агентов и Bursting

> 🗣️ **Сомнение автора:** *«Не задохнутся ли 2–3 агента на четвертинке ядра? А если нарезать медиа через ffmpeg или собирать проект?»*🧠 **Ответ архитектора: Два фундаментальных принципа:**
>
> 1. **Природа AI-агентов (I/O Bound):** Агенты формируют текстовый промпт и отправляют HTTPS-запрос к API Gemini/OpenAI. **95% времени процесс спит в ожидании токенов по сети**, потребляя всего 0.1%–0.8% CPU. Тяжелейшие тензорные вычисления идут на TPU Google, а не на вашей ВМ!
> 2. **Технология CPU Bursting:** Пока машина простаивает, она накапливает процессорные кредиты. В момент сборки проекта или работы `ffmpeg` гипервизор кратковременно выдает **до 100% мощности обоих ядер (до 200% в htop)**, мгновенно решая пиковую задачу. В тарифе `e2-small` (v2.0) база в 2 раза выше, а 2 ГБ физической ОЗУ дают агентам полную свободу!

## 6. 🔬 Препарирование скрытых настроек GCP (По вопросам автора)

<details class="chapter-details">
<summary><b>📖 Развернуть / Свернуть Главу 6</b> <i>(нажмите для переключения)</i></summary>

### 6.1. Graceful shutdown и host error recovery

- **Host error recovery policy:** Строго выставляем **`Default recovery (Restart VM instance)`**. Если в дата-центре выйдет из строя физическая планка памяти или серверный блок питания, Google автоматически перемонтирует ваш диск на исправный хост и запустит машину без вашего участия.
- **Graceful shutdown period:** Оставляем дефолтные 300 секунд (5 минут). Это дает Linux достаточно времени, чтобы корректно завершить процессы и сбросить кэш на диск (`sync`).

### 6.2. On VM termination: Stop, а не Delete (Смертельная ловушка)

> [!WARNING]
> В некоторых конфигурациях GCP переключатель действия при завершении выставлен в `Delete`! В этом случае при любом вытеснении машина **безвозвратно удаляется вместе со всеми данными**.
> **МЫ СТРОГО ВЫБИРАЕМ `Stop`!** Диск остается в полной сохранности.

### 6.3. Data protection: Ловушка скрытых бэкапов

В настройках Snapshot schedule строго выставляем **`None`**. Автоматические снапшоты не входят в бесплатные квоты и накручивают от \$2 до \$5 в месяц скрытых списаний.

### 6.4. Observability: Почему Ops Agent выключаем

Google Cloud Ops Agent (мониторинг логов) потребляет от **150 до 220 МБ RAM**. На бюджетной машине он съедает львиную долю свободной памяти и провоцирует аварии OOM-killer. **Галочку установки снимаем обязательно!**

### 6.5. Сетевой ребус: Почему КАТЕГОРИЧЕСКИ НЕЛЬЗЯ отключать External IP

> [!CAUTION]
> **Никогда не выбирайте `External IP: None`!**

1. **Сервер теряет выход в интернет:** Без внешнего адреса перестают работать команды `apt update`, `pip install`, `npm install`, git clone, а также исходящие соединения к Telegram API, OpenAI и Gemini.
2. **Ловушка Cloud NAT Gateway (~\$32+/мес):** Единственный официальный способ дать интернет серверу без внешнего IP в GCP — это поднять шлюз Cloud NAT, минимальная абонплата за который составляет **~\$32.00 в месяц**!
3. **Бесплатность и дешевизна Ephemeral IPv4:** В Always Free динамический IP для `e2-micro` бесплатен (\$0.00), а на Spot VM он стоит всего **~\$1.83 в месяц** благодаря скидке 50%.

## 8. 🧙‍♂️ Секретное оружие: Магия Swap в Linux (Из 2 ГБ делаем 8 ГБ)

<details class="chapter-details">
<summary><b>📖 Развернуть / Свернуть Главу 8</b> <i>(нажмите для переключения)</i></summary>

### 8.1. Зачем нужен Swap и почему без него убиваются процессы

При запуске Node.js воркеров или Python-агентов память быстро заполняется. Когда физическая RAM подходит к концу, ядро Linux вызывает **OOM-Killer (Out-Of-Memory Killer)**, который принудительно «казнит» самый прожорливый процесс. Swap-файл на скоростном Balanced SSD решает эту проблему.

### 8.2. Таблица подбора размера SWAP под ОЗУ сервера

| Объем ОЗУ (RAM)          | Рекомендуемый SWAP | Итоговая виртуальная память | Типовая нагрузка и задачи                                                        |
| :------------------------------- | :------------------------------ | :--------------------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| **1 ГБ** (`e2-micro`)  | **4 ГБ**                | **5 ГБ**                                     | Telegram-боты, легкие AI-агенты, Cockpit UI, SQLite                                    |
| **2 ГБ** (`e2-small`)  | **4 – 6 ГБ**           | **6 – 8 ГБ**                                | Тяжелые Node.js воркеры, браузерная автоматизация, Docker         |
| **4 ГБ** (`e2-medium`) | **4 ГБ**                | **8 ГБ**                                     | Несколько параллельных агентов, локальные векторные БД |

### 8.3. Тонкий тюнинг параметров ядра Linux против OOM-Killer

| Параметр ядра | Дефолт | Тюнинг v2.0 | Физический смысл и почему это защищает процессы                                                                                                                                                               |
| :------------------------ | :----------- | :---------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vm.swappiness`         | `60`       | **`10`**  | Запрещает ядру панически сбрасывать активный код в swap заранее. Подкачка включается только при реальном исчерпании физической памяти. |
| `vm.vfs_cache_pressure` | `100`      | **`50`**  | Дольше удерживает файловые индексные дескрипторы (inodes/dentries) в RAM, ускоряя дисковые операции и git в 2 раза.                                                          |

### 8.4. Готовый Bash-скрипт настройки памяти:

```bash
# 1. Создание файла подкачки (4 ГБ для e2-micro или 6 ГБ для e2-small)
sudo fallocate -l 4G /swapfile || sudo dd if=/dev/zero of=/swapfile bs=1M count=4096
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 2. Автозагрузка в /etc/fstab
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 3. Тюнинг ядра Linux
sudo tee /etc/sysctl.d/99-swap.conf << 'EOF'
vm.swappiness=10
vm.vfs_cache_pressure=50
EOF
sudo sysctl --system

# 4. Проверка итоговой памяти
free -h
```

> 🗣️ **Вопрос автора:** *«А разве эти деньги будут капать в копилку? Это же бонусные промокоды от Google, а не реальные рубли на карте!»*

## 13. 🚀 Эволюция v2.0: Serverless Event-Driven Auto-Restarter и бесплатный домен на 1 год

<details class="chapter-details">
<summary><b>📖 Развернуть / Свернуть Главу 13</b> <i>(нажмите для переключения)</i></summary>

В версии 2.0 мы вывели надежность Spot-сервера на космический уровень, решив две главные проблемы прерываемых машин: **автоматический подъем после вытеснения** и **сохранение постоянного адреса при смене динамического IP**.

### 13.1. Почему отброшен локальный демон `spot-watchdog.sh`?

В ранних прототипах разработчики часто ставили скрипт-демон на самой ВМ, опрашивавший метаданные GCP (`http://metadata.google.internal`) каждые 5 секунд. Мы категорически отказались от этого подхода:

1. **Бессмысленный расход CPU:** Постоянный цикл в фоне расходует такты процессора shared-core машины.
2. **Мертвая машина не может поднять сама себя:** Если Google Cloud выключил ВМ, виртуальный процессор остановлен. Никакой скрипт на выключенном сервере не выполнится и не сможет послать API-запрос на включение.
3. **Риск мгновенной остановки:** При резком отзыве мощностей у машины есть всего до 30 секунд. Если скрипт завис в сетевом таймауте, уведомление даже не успеет уйти.

### 13.2. Облачная бессерверная архитектура Google Cloud (Event-Driven)

Сторож v2.0 вынесен **целиком наружу — в бессерверное облако Google Cloud**. На самой ВМ не работает ни единого лишнего процесса!

```
┌──────────────────────────────────────┐
│ Google Cloud Audit Logs              │
│ (Событие: compute.instances.preempted)│
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│ Cloud Logging Sink                   │ (spot-preemption-sink)
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│ Cloud Pub/Sub Topic                  │ (spot-preempted-events)
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│ Push Subscription with Retry Policy  │ (Экспоненциальная лестница:
│ Exponential Backoff                  │  1м ➔ 5м ➔ 10м ➔ 20м ➔ 40м ➔ 60м)
└──────────────────┬───────────────────┘
                   ▼
┌──────────────────────────────────────┐
│ Cloud Function: spot-restarter       │ ──► Compute Engine API: instances.start()
│ 512 MB RAM (Python 3.11, Serverless) │ ──► Telegram Bot: Оповещение + кнопка [ 🚀 Включить вручную ]
└──────────────────────────────────────┘
```

#### Экспоненциальная лестница повторов (Exponential Backoff):

Когда Spot-машину отзывают, это значит, что в дата-центре прямо сейчас физически нет свободных ресурсов. Если слать запрос `instances.start` каждую секунду, Google заблокирует проект ошибкой квоты (`ZONE_RESOURCE_POOL_EXHAUSTED`).
Pub/Sub Push Subscription автоматически повторяет попытки по умному графику: **1 мин ➔ 5 мин ➔ 10 мин ➔ 20 мин ➔ 40 мин ➔ 60 мин**, пока машина гарантированно не включится.

#### Команды развертывания через `gcloud CLI`:

```bash
# 1. Создание топика очереди сообщений
gcloud pubsub topics create spot-preempted-events

# 2. Создание фильтра в Cloud Logging
gcloud logging sinks create spot-preemption-sink \
    pubsub.googleapis.com/projects/YOUR_PROJECT_ID/topics/spot-preempted-events \
    --log-filter='resource.type="gce_instance" AND jsonPayload.event_subtype="compute.instances.preempted"'

# 3. Выдача прав сервисному аккаунту на публикацию в топик
SINK_SA=$(gcloud logging sinks describe spot-preemption-sink --format='value(writerIdentity)')
gcloud pubsub topics add-iam-policy-binding spot-preempted-events \
    --member=$SINK_SA \
    --role=roles/pubsub.publisher
```

#### Боевой Python-код Cloud Function `spot-restarter` (`main.py`):

```python
import base64
import json
import os
import requests
from googleapiclient import discovery

def auto_restart_spot(event, context):
    """Бессерверный обработчик вытеснения Spot VM из Pub/Sub."""
    project = os.environ.get('GCP_PROJECT')
    zone = os.environ.get('VM_ZONE', 'us-central1-b')
    instance = os.environ.get('VM_NAME', 'free-server')
    tg_token = os.environ.get('TELEGRAM_BOT_TOKEN')
    tg_chat_id = os.environ.get('TELEGRAM_CHAT_ID')

    compute = discovery.build('compute', 'v1')
    try:
        request = compute.instances().start(project=project, zone=zone, instance=instance)
        response = request.execute()
        msg = f"⚠️ Spot-сервер <b>{instance}</b> был отозван Google Cloud.\n🚀 <b>Команда на автозапуск успешно отправлена!</b>"
    except Exception as e:
        msg = f"❌ Ошибка автозапуска Spot-сервера <b>{instance}</b>: {e}\n⏳ Включена экспоненциальная очередь повторов Pub/Sub."

    # Отправка Telegram-оповещения с инлайн-кнопкой
    if tg_token and tg_chat_id:
        url = f"https://api.telegram.org/bot{tg_token}/sendMessage"
        payload = {
            "chat_id": tg_chat_id,
            "text": msg,
            "parse_mode": "HTML",
            "reply_markup": {
                "inline_keyboard": [[
                    {"text": "🚀 Включить сервер вручную", "callback_data": f"start_{instance}"}
                ]]
            }
        }
        try:
            requests.post(url, json=payload, timeout=10)
        except Exception:
            pass
```

### 13.3. Решение смены динамического IP: Бесплатный домен на 1 год + Cloudflare DDNS

Поскольку внешний IP на Spot динамический, при каждом автоперезапуске адрес меняется. Чтобы не покупать платный Static IP от Google, используется красивое решение:

1. **Бесплатный домен на 1 год:** Получаем доменное имя бесплатно через GitHub Student Developer Pack, Namecheap, Cloudflare Registrar или акции регистраторов.
2. **Делегирование на Cloudflare (\$0):** Домен подключается к бесплатному DNS Cloudflare.
3. **Скрипт Dynamic DNS (DDNS):** На сервере настраивается легковесный скрипт в cron или systemd-service, который при старте машины или раз в 10 минут запрашивает свой внешний IP (`curl ifconfig.me`) и обновляет DNS A-запись через Cloudflare API за 2 секунды:

```bash
#!/usr/bin/env bash
# cloudflare-ddns.sh
ZONE_ID="YOUR_CLOUDFLARE_ZONE_ID"
RECORD_ID="YOUR_DNS_RECORD_ID"
API_TOKEN="YOUR_CLOUDFLARE_API_TOKEN"
DOMAIN="myserver.mydomain.com"

IP=$(curl -s http://checkip.amazonaws.com || curl -s https://ifconfig.me)

curl -s -X PUT "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/dns_records/$RECORD_ID" \
     -H "Authorization: Bearer $API_TOKEN" \
     -H "Content-Type: application/json" \
     --data "{\"type\":\"A\",\"name\":\"$DOMAIN\",\"content\":\"$IP\",\"ttl\":120,\"proxied\":false}"
```

Теперь ваш сервер всегда доступен по постоянному доменному адресу `myserver.mydomain.com`!
